AI 伴读开源项目选型报告

面向「导入电子书 → AI 改写助读 → 分段讨论 → 继续下一段」这一阅读工作流
数据来源：GitHub REST API 实测抓取 ｜ 截止 2026-09-27

一句话结论：有，而且不少，但没有一个项目把你说的两件事同时做到位。

「选中一段 → 让 AI 解释/简化/改写 → 侧栏追问」这条链，已有多个项目做得很成熟；但「让 AI 把整本书一段一段预先润色好，然后你直接读改写稿」这件事，市面上基本没人做成一等公民功能——都是要你手动选中才触发。这个缺口对你的场景反而是机会。

如果你只是想找个能用的：ReadAny（最成熟）或 ReadAware（体验最好、最接近「伴读」）。如果你想要的就是你描述的那套流程：先看 聊书，但要接受它是个人新项目。

③ 重点候选详解

ReadAny

综合首选
github.com/codedogQBY/ReadAny
2,669 ★211 fork TypeScriptTauri + Expo 最后提交 2026-09-26GPL-3.0（仓库标 Other）
  • 导入：声称支持 8+ 格式，本地优先（SQLite + 本地向量库），书不进云。
  • 改写：没有「整本预改写」；提供即时翻译 + 解释 + 语义检索，选中段落让 AI 处理。
  • 讨论：RAG 全书问答，可问主题、脉络、翻译，不局限当前段。
  • 模型：OpenAI / Claude / Gemini / Ollama（本地）/ DeepSeek，自带 key。
  • 周边：5 色高亮、Markdown 笔记导出到 Obsidian、Edge TTS 朗读、WebDAV/S3/局域网同步、阅读统计热力图。

要注意：355 个未关 issue，仓库 license 字段标的是 "Other"（官网写 GPL-3.0）——想拿它的代码做二次开发，先把这个搞清楚。

ReadAware

最接近「伴读」
github.com/ahpxex/read-aware
392 ★34 fork TypeScriptTauri 2 + React 19 最后提交 2026-09-27AGPL-3.0
  • 导入：EPUB / MOBI / AZW3 / FB2 / PDF / TXT / HTML / CBZ / CBR 共 9 种，统一阅读模型，不用转格式。
  • 阅读范式：「逐句阅读」——一屏只推一句，天然适配你说的「读一段、停下来想一想」。
  • 改写：不是自动铺开，而是在页面上选段落 → 直接问 AI「这段在说什么 / 换成人话」，回答进侧栏，不离开书。
  • 讨论：一个带工具调用和长期记忆的 Agent，跨书积累你读过什么、标注过什么，不是无状态问答机器人。
  • 扩展：沙箱插件市场——朗读音色、主题、词典、RSS 源、新的 Agent 工具都能装。
  • 同步：端到端加密，走官方 relay 或你自己的 WebDAV。
选它的理由：这个项目的产品哲学就是「AI 待在阅读旁边，而不是接管阅读」，跟你的诉求最同频；跨 macOS / Windows / Linux / Android / iOS。
要注意：AGPL-3.0——如果你打算把它的代码揉进自己的商业项目，AGPL 的网络分发条款会咬人，只能当参考实现读，别直接抄。

聊书 · AI 带读电子书

最贴你的描述，但没人验证过
github.com/timno1988-hub/liaoshu-ai-reader
0 ★JavaScript React + Vite + Capacitor建库 2026-09-15MIT
  • 三种 AI 模式：带读（逐页总结、解读、点出术语与论证结构）／讨论（统领全书的教练，基于全书检索，不做逐页重复）／费曼（让你复述，AI 打分并针对薄弱点重练）。
  • 学习档案：每本书维护一份读者画像（目标 / 已掌握 / 薄弱点 / 费曼卡点），三个模式共享。
  • 导入：EPUB / PDF / TXT / MOBI / AZW3；按屏精确分页、横向滑动翻页、朗读逐句高亮。
  • 部署：同一套代码出 Web/PWA 和安卓 APK；数据全在本地 IndexedDB。
  • 模型：自带任意 OpenAI 兼容 key（内置 DeepSeek 预设），key 只存本机。
为什么值得看：它把你说的「读原文 / 让 AI 重讲一遍 / 随时切进讨论 / 讨论完继续」直接做成了三个可切换的模式，还配了学习档案——这正是你在描述的工作流。
为什么不能盲信：0 star、0 fork、建库才十来天、单人项目。代码可以当参考，别指望长期维护。好在是 MIT，思路可以直接拿来用。

Marginalia

「选中即改写」做得最顺
github.com/EurFelux/marginalia
5 ★桌面端 最后提交 2026-09-24GPL-3.0
  • 核心交互：在 ePub 或带文本层的 PDF 里选中一段，浮动工具条立刻给出 解释 / 翻译 / 摘要 三个一键动作，或直接自由提问；答案流式吐进侧栏，阅读不断。
  • 透明的上下文：每次提问带了哪些上下文，会显示成可开关的「筹码」——你的选区、所在段落、本章摘要、全书摘要，各自可勾可弃。你永远知道 AI 看到了什么，这点很少有项目做到。
  • 陪伴感：可以给助手起名、设人设和长期指令；有跨会话记忆，且每条记忆你都能看、能改、能删、能整体关掉；每本书的对话独立存档。
  • 朗读：按段落念，念到哪句高亮哪句并自动滚动，跨章节连续。
  • 其他：5 色高亮 + 便签 + 每本书一份 Markdown 笔记本；Apple Books 风格的封面墙书库；本地优先，BYOK，支持任意 OpenAI 兼容端点。
选它的理由：如果你最痛的是「文绉绉读不动」，它「选中 → 立刻给出白话版」的手感是这个列表里最好的。
要注意：只有 5 颗星，非常新的单人项目；格式只有 ePub/PDF；macOS 未公证，首次打开要手动放行。

reader-source

macOS 原生 + 原地改写
github.com/Marvy101/reader-source
57 ★Swift / SwiftUI 最后提交 2026-09-20MIT

ReadBridge

语言学习向，逐句讲解
github.com/WindChimeEcho/read-bridge
337 ★42 fork TypeScript / Next.js最后提交 2026-09-18MIT
  • 逐句推进：按句为单位读，一句一句过，天然形成「读一句 → 看 AI 讲解 → 下一句」的节奏。
  • n+1 可理解输入：理论基石是 Krashen 的 i+1——每 100 词只有 1-2 个生词才叫有效输入；AI 用目标语言解释，不做翻译回母语。
  • 难度可调：按你自评的水平选/写 prompt 模板，AI 的讲解深度跟着变。
  • 进度跨章节跨书保存，纯浏览器可用。
选它的理由：你自己就在做英语学习应用，这个项目把「用 AI 降低原文难度」这件事讲得最清楚，而且 MIT、活跃、有社区。它的 prompt 设计与难度分级思路可以直接借鉴。
要注意：它不是通用电子书阅读器，偏学习工具，格式支持窄。

④ 两个值得注意的空白

空白一：没有人把「整本预改写」做成一等公民

你描述的「让 AI 把一段一段重新润色一遍给我读」，本质是给同一本书生成第二条阅读线——原文一层、改写稿一层，双栏或一键切换，离线可读、可缓存。

我翻遍上面这些项目，全都是「选中才触发」的按需模式。没有一个是导入时就整本跑一遍、把改写稿落库、阅读时无缝对照的。原因是成本与体验的权衡：整本改写 token 消耗大、等待久，而按需触发零浪费。

但对你说的场景（生僻书读得慢、口水书全是废话），按需触发其实不解决问题——你还是得先读懂才能判断哪段需要改写。这个缺口是真实的。

空白二：工具只会「降难度」，不会「提稠密度」

你抱怨的两类书，需求方向其实是相反的：

  • 文绉绉、生僻词多的 → 需要降难度：简化、白话化、拆句子。几乎所有工具都在做这个。
  • 商业畅销书、全是口水话的 → 需要提稠密度：压缩掉铺垫和重复，只留论点、证据、结论，把 300 页压成 30 页的骨架。

后者我没找到任何成熟实现。摘要功能是「章末给你一段总结」，不是「把正文本身的冗余挤掉、重写成紧凑版让你读」。这可能是比第一个更有价值的切入点。

⑦ 建议的下一步

三条路，按投入从小到大：

  1. 今天就用起来：下 ReadAny 或 ReadAware 的现成安装包，各读一章你手头最难受的那本书，试试「选中 → 让 AI 换人话 → 追问 → 继续读」顺不顺。半小时能判断出够不够用。
  2. 想要你描述的那套流程：把 聊书（MIT，React）clone 下来跑一遍。它的「带读 / 讨论 / 费曼」三模式拆分，本身就是一份不错的产品设计参考——即使你最后不用它。
  3. 想自己做（我认为最值得）：你在做英语学习应用，本来就熟悉 Next.js + Prisma + Postgres。真正没被占领的是上面那两个空白——整本预改写 + 原文/改写稿双层阅读线，以及反向的「提稠密度」压缩读法。现有的都是「选中才触发」，你把「导入即处理、双栏对照、离线可读」做出来，就是差异化。
