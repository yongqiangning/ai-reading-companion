一个纯前端、跑在 Chrome 里的中文电子书 AI 伴读工具
v1.3 ｜ 2026-09-28 ｜ 状态：已确认，按本文档实现

v1.3 相对 v1.2 的修订（试用后反馈）：

  1. 讨论不设知识边界。原提示词把"只基于给出的原文回答、超范围必须说'这超出了我能看到的内容'"写成硬约束，导致问个作者原名都被拒答。改为：给出的原文是补充背景，AI 可以自由使用自己的知识，讨论允许发散。只在用户明确问"这一段/这本书里怎么写的"时才以原文为准。
  2. 带修饰键的组合键一律不拦。Cmd+C 曾被「C 长文」吃掉，且因为调了 preventDefault，连复制都失败。
  3. 带修饰键的滚轮也不拦（Cmd+滚轮 / 触控板捏合是缩放）。

v1.2 相对 v1.1 的修订（试用后反馈）：

  1. 讨论抽屉里不再复制一份当前正文。原文就在左边、还在虚化上下文里，复制一份只是重复，还白占版面。
  2. 讨论抽屉没有任何空态文案。不给"这一屏还没聊过"、不给提问示例。没聊过就是空白等输入，发出第一条后才显示对话记录。
  3. 没有对象的操作收起。一条回复都还没有时，「重新生成回复」隐藏。

v1.1 相对 v1.0 的修订（试用后反馈）：

  1. 焦点模式不再隐藏前后文。原方案是"屏幕上只有当前这一屏"，实际读起来完全没有上下文。改为：当前屏清晰居中，前后各 12 屏照常渲染，按距当前屏的远近逐级模糊、逐级变淡，屏幕上下缘再淡出。
  2. 翻页键改为方向键。上一屏 = ↑（不再用 Shift+空格）；下一屏 = 空格 或 ↓。鼠标滚轮一次滑动走一屏。
  3. 回车与 Tab 对调。回车 = 切换原文 / 润色版；Tab = 进入讨论。

1. 项目定位

你要解决的问题很具体：中文书读起来太费劲。两种情况——文字水平远高于你的书，生僻词和长句让你读得很慢；以及全是口水话的商业畅销书，读了半天没有信息量。两种情况的解法是相反的，但共同点是：你需要一个能按你的水平重新组织原文的中间层。

市面上现有的工具（ReadAny、ReadAware、Marginalia 等）都只做到了「选中一段 → 让 AI 解释」，属于按需触发：你还是得先读懂原文，才知道哪一段需要改。这个工具反其道而行——把 AI 改写做成一等公民，让你可以整本书都以改写稿的形式读下去。

一句话定位：把一本中文书，按你的节奏，一屏一屏地、用 AI 重写过的语言读下去；读到有意思的地方，随手进入与 AI 的讨论；聊完继续往下。

3. 目标与非目标

目标

  • 零后端、零安装。双击 main.html，在 Chrome 里打开就能用。不启动服务、不装依赖、不注册账号。
  • 一屏一段的心流阅读。当前这一段清晰并停在视线正中，前后的篇幅都还在——只是虚化了。眼前始终是一本书，不是一段孤立的文字。
  • 润色稿可以一直读下去。一键切到润色版后，往后每一屏都是改写稿，不用逐屏确认。
  • 讨论随手可达。读到有意思的地方按一个键就能和 AI 聊，聊完接着往下读。
  • 关掉浏览器不丢东西。下次打开直接回到上次那一屏，进度、润色稿、讨论记录都在。

非目标（明确不做）

不做的原因
任何形式的后端服务、账号、云同步你的明确要求；实测 DeepSeek 接口允许 file:// 直连，无需中转
MOBI / AZW3 / PDF 解析Kindle 格式浏览器端无现成解析库，PDF 分段不可靠；用 Calibre 转 EPUB 更划算
跨语言翻译（英译中等）你的场景是中文书的中文重写
划词问 AI、高亮、笔记会引入第二套交互，稀释焦点阅读的纯粹性
Token 用量与费用统计你不需要
全书检索 / RAGAI 额外获得的背景限定在「当前屏 + 前 10 屏」，token 完全可控；但它自己的知识不受此限
移动端 / 响应式适配目标是桌面 Chrome 本地使用
多标签页 / 多窗口同步单页应用，单窗口使用

4. 核心概念

这几个词贯穿全文，先定义清楚。

概念定义
屏（屏单元 / unit）阅读的最小单位。默认一个自然段算一屏；自然段超过阈值（默认 160 字）时，在句末标点处自动切成多屏，累积到接近阈值切一刀。一屏必然是一个完整的语义块。
原文书里的原始文字。
润色稿AI 按你的水平重写过的这一屏。信息量不增不减，只换说法：生僻词换常用词、长句拆短句、书面腔换口语。不是摘要，不是翻译，不是注释。
焦点模式默认阅读视图。当前一屏吸在视线正中并保持清晰；前后各渲染若干屏（默认 12 屏）作为上下文，按距当前屏的远近逐级虚化、逐级变淡，屏外缘再淡出。正文不随鼠标滚动，一屏一屏走。
长文模式临时切换的连续滚动视图，用于通读整章。整章连续排版，一键切回焦点模式。
讨论以某一屏为锚点、和 AI 的对话。对话按屏独立存档，翻回该屏可以接着聊。
阅读位你当前停在哪一屏（书 / 章 / 屏三级定位）。

5. 功能清单

P0 — 核心闭环，缺一不可

功能说明
导入 EPUB选择或拖入 .epub 文件；解析出书名、作者、封面、目录、章节正文；切成屏单元。
书架列出已导入的书（封面、书名、作者、进度百分比）；可打开、可删除。首次打开时就是一个"选一本书"的界面。
焦点阅读当前一屏居中并清晰，前后各若干屏按距离逐级虚化当上下文；跨章连续，章题随上下文一起出现。字号行距舒适。
翻屏下一屏 / 上一屏；跨章节自动衔接；到底/到顶有明确反馈。
润色稿生成对当前屏调用 DeepSeek 生成改写稿，结果落库缓存，二次进入秒开。
润色模式切换切换后持续生效：往后每一屏都优先显示润色稿；再切回则显示原文。
随读随备进入润色模式后，后台自动为接下来的 5 屏预生成润色稿（串行，1 并发），保持缓冲。
讨论右侧抽屉展开对话；AI 上下文 = 当前屏全文 + 前面 10 屏；流式输出。
讨论留痕聊过的屏在进度条与目录上有标记；翻回该屏时自动载入当时的完整对话，可继续。
进度持久化书、阅读位、润色稿、讨论记录全部存 IndexedDB；重开直接恢复。
目录跳转侧栏目录，点章节名跳到该章第一屏。
设置DeepSeek API Key、模型名、讨论上下文屏数（默认 10）、预生成缓冲屏数（默认 5）、字号、主题（浅色/米黄/夜间）。

P1 — 体验完善，第二阶段

功能说明
连续长文模式一键切整章连续排版，可自由滚动、可选中文字；切回焦点模式时以最后停留的位置为准。
润色稿与原文对照在长文模式或焦点模式下，单屏展开原文与润色稿并排对照。
生成失败重试单屏生成失败时给出明确提示与"重试"入口，不静默失败。
数据导出 / 导入把全部数据（书 + 进度 + 润色稿 + 讨论）导出成一个 JSON 文件，换浏览器或备份用。
快捷键帮助页按 ? 浮出快捷键清单。
朗读 AI 回复讨论里 AI 的回复边生成边读出来，按句切分，不用等整段写完。默认用系统语音（零依赖、即时）；设置里可切到本地服务 Qwen3-TTS（MLX 跑 GPU，完全离线，9 个预设音色含中文女声/男声/方言）。走流式：第一个音频块 0.3～0.5 秒就回来，点发送后约半秒出声，不用等整句合成完。
章末小结读完一章时，AI 给一段本章要点回顾（可选开关）。

P2 — 以后再说

  • 自定义改写强度（三档：轻度润色 / 标准白话 / 极简口语）
  • 按书设置默认阅读模式（有的书永远读润色版）

6. 关键流程

6.1 首次打开

  1. 打开 main.html → 检测到没有书 → 显示欢迎/选书界面。
  2. 显示一个大拖放区 + "选择 EPUB 文件"按钮，旁边一行小字说明：目前只支持 EPUB。MOBI / AZW3 / PDF 建议先用 Calibre 转成 EPUB。
  3. 用户选文件 → 解析（带进度提示，大书可能要几秒）→ 用内容 SHA-256 生成书籍 ID。
  4. 如果这本书已经在书架里（同一 ID）→ 直接跳到它上次的阅读位，不重复导入。
  5. 否则入库，进入第一章第一屏。

6.3 讨论循环

[Tab]  → 右侧抽屉展开，载入该屏的历史对话（若有）
       → 没有历史对话时抽屉里就是空白：不复制当前正文、不放任何引导文案
       → 光标自动落到输入框
       → 提问 → 流式返回
       → 继续追问任意轮
       → 该屏标记为"已讨论过"
[Esc]  → 抽屉收起，回到焦点阅读，停留在同一屏
[空格] → 抽屉收起并前进到下一屏（"讨论完接着读"）
[Tab]  → 讨论中再按一次：放开输入框、抽屉不关，键盘交还给阅读

AI 在讨论中额外获得的背景（每次都完整给出，不做检索）：

  • 书名、当前章名、当前是第几屏 / 本章共几屏
  • 当前屏的完整原文（即使当前显示的是润色稿，也给它原文）
  • 当前屏所属自然段的全文（这一屏可能只是该自然段被切出来的一部分）
  • 前面 10 屏的原文（可调）

这些内容是"补充背景"，不是"AI 的知识边界"。讨论是发散的，AI 必须能自由使用自己的知识回答人名、作者、年代、术语、历史背景、相关著作等——绝不能出现"这超出了我能看到的内容"这类回答。只有当用户在明确问"这一段 / 这本书里是怎么写的"时，才以上面给的原文为准；原文里确实没写，直说这一段里没有，之后照样可以给出它知道的。

唯一保留的约束是不许把编造的细节说成是原文里的：涉及本书具体情节、章节安排、版本差异这类容易记错的事，若来自模型自身知识，需用"据我所知"这类措辞。

6.4 二次打开

  1. 打开 main.html → 读 IndexedDB → 有上次的书 → 直接恢复到上次的阅读位，包括当时是原文还是润色模式、字号主题等。
  2. 整个恢复过程不出现在中间界面，不要求任何点击。
  3. 左上角提供"书架"入口，可以换书或导入新书。

┌──────────────────────────────────────────────────────────────────────┐ │ 《书名》 第三章 · 第 12/48 屏 [原文|润色] ≡目录 ⚙设置 ☰书架 │ ├──────────────────────────────────────────────────────────────────────┤ │ （虚）上一屏…… │ │ （虚）上上屏…… │ │ │ │ 他站在窗前，手里攥着那张已经揉皱的电报，半晌没有说话。 ←清晰 │ │ │ │ （虚）下一屏…… │ │ （虚）下下屏…… │ ├──────────────────────────────────────────────────────────────────────┤ │ ▓▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░░░░ 25% · 已讨论 3 屏 │ └──────────────────────────────────────────────────────────────────────┘ 空格/↓ 下一屏 ↑ 上一屏 回车 润色版 Tab 讨论 C 长文 T 目录 ? 帮助

「虚」不是隐藏，是按距离递减的模糊与透明度：紧邻的一屏只有轻微虚化，越远越糊、越淡，屏幕上下缘再淡出到背景里。跨章时章题也会作为上下文出现。当前屏始终被吸在视线正中。

7.2 讨论展开

┌───────────────────────────────────┬──────────────────────────────────┐ │ 《书名》 第三章 12/48 [原文] │ 这一屏的讨论 ✕ 收起 │ ├───────────────────────────────────┼──────────────────────────────────┤ │ │ │ │ │ │ │ 他站在窗前，手里攥着那张已经 │ │ │ 揉皱的电报，半晌没有说话。 │ 你：他为什么不直接说？ │ │ │ AI：因为前面提到电报是……（流式）│ │ 楼下的梧桐叶落了一地，被风卷 │ │ │ 起来又落下。 │ 你：▌ │ │ │ ───────────────────────────── │ │ │ [ 继续读 → ] [ 重新生成回复 ] │ └───────────────────────────────────┴──────────────────────────────────┘

抽屉里不再复制一份当前正文——原文就在左边、还在虚化上下文里，复制一份只是重复，也白占版面。所以抽屉打开时没有任何空态文案：没聊过就是空白，等输入；发出第一条后才出现对话记录。

7.3 长文模式

整章连续排版，正常滚动，字号与焦点模式一致。顶部保留一个"回到焦点模式"的按钮，并在滚动时实时显示当前位置对应第几屏。点一段即选中，再点一下吸附回该屏的焦点阅读；在长文里按 Tab 可以直接讨论选中的那一段。

8. 快捷键

翻屏用空格 / 方向键，切换与讨论分别落在回车 / Tab。所有快捷键在底部常驻提示，按 ? 看完整清单。

鼠标滚轮下一屏 / 上一屏焦点模式不滚动正文，一次滑动正好走一屏

带 Cmd / Ctrl / Alt 的组合键一律放行，页面不拦也不 preventDefault：Cmd+C 复制、Cmd+R 刷新、Ctrl+A 全选、Cmd+滚轮 / 触控板捏合缩放都要正常工作。原因是单字母快捷键（C 长文、T 目录）只看 e.key 就会被 Cmd+C 误命中，而且拦截后连复制本身都会失效。Shift 不在此列——? 本身依赖 Shift。

输入焦点保护：只要焦点在输入框内（讨论输入框、设置里的 Key 输入框等），所有单字母快捷键与空格一律不生效，正常输入。这是必须做对的细节——否则打字时按空格会翻屏。

9. 数据模型

全部数据存在 IndexedDB 的单一数据库里，按对象仓库分开。

books       { id, title, author, coverBlob, addedAt, lastOpenedAt,
              chapters: [ { title, units: [ { id, text, srcParaIndex, kind } ] } ] }
              id = SHA-256(文件字节)，用于去重
              kind = 'whole'（整段就是一屏） | 'part'（超长段被切出来的一屏）

progress    { bookId, chapterIndex, unitIndex, mode, updatedAt }
              mode = 'original' | 'polished'  → 记住你要不要一直读润色版

rewrites    { bookId, unitId, text, model, createdAt }
              按屏缓存，命中即秒开

chats       { bookId, unitId, messages: [ { role, content, at } ], updatedAt }
              按屏存对话；存在即视为"已讨论"

settings    { apiKey, model, baseUrl, contextUnits, prefetchUnits,
              fontSize, theme, lineHeight, splitThreshold }

身份与去重：同一本 EPUB 无论从哪个路径导入，内容哈希相同就视为同一本，不重复入库、且能正确接上原有进度。

10. 技术方案

10.1 为什么可以零后端

已实测确认（本机 Chrome，真实浏览器环境）：

能力结论
DeepSeek 接口直连可行。对 Origin: null 返回 access-control-allow-origin: null，允许 file:// 页面直接 POST
IndexedDB可用，配额约 3 GB（navigator.storage.estimate()）——书、润色稿、对话都放得下
localStorage可用，上限约 9.5 MB。只用来放小设置，不放书
crypto.subtle可用，用于算文件哈希
本地文件系统 API可用（file:// 是安全上下文），P1 的导出功能可用

10.2 必须绕开的坑

不能用 ES Module。 <script type="module"> 在 file:// 下会被 CORS 直接拦掉。全部脚本必须用经典 <script src="..."> 引入，模块化靠 IIFE + 全局命名空间实现。

不能 fetch 本地文件。 读磁盘文件只能走 <input type="file"> / 拖放 + FileReader / arrayBuffer()。

不依赖 CDN。 外部依赖全部落到本地 assets/vendor/，保证断网也能完成导入与阅读（只有调 AI 时需要网络）。

能从 file:// 直连本机服务，但服务端必须带 CORS 头。 页面发出的请求 Origin 是字面量 null（不是"没有来源"），本地朗读服务的预检会因为没有 Access-Control-Allow-Origin 被浏览器拦掉。别以为是同在本机就免检——实测过，缺这个头就是 Failed to fetch。

10.4 DeepSeek 接口约定

对齐你 English 项目里已验证的用法，保持一致：

项值
端点https://api.deepseek.com/chat/completions
模型deepseek-v4-flash（可在设置里改）
鉴权Authorization: Bearer <API Key>，Key 存在本机 IndexedDB，不上传任何地方
思维链请求体带 thinking: { type: "disabled" }。v4 模型默认开思维链，会把正文塞进 reasoning_content，导致解析取不到内容
重试429 与 5xx 退避重试，最多 2 次；其余错误直接报错
超时非流式 30 秒；流式按空闲超时判定
润色非流式（后台批量跑，不需要展示过程）
讨论流式 SSE，逐字输出

10.5 提示词要点

润色（约束比技巧重要）

  • 保留原意与全部信息，不增不减；不添加原文没有的解释、评论、过渡句
  • 生僻词换常用词，长句拆短句，书面腔换口语
  • 不输出任何前言、说明、引号或 Markdown 标记——直接给正文，否则会污染阅读界面
  • 输入是「一屏」，输出长度应与原文同一量级（防止模型擅自扩写或缩成摘要）

讨论

  • 角色是博学、诚实、不奉承的阅读伙伴；禁止"很好的问题"这类客套
  • 严格基于给定上下文回答；超出范围必须明说，禁止编造
  • 中文、简洁；用户要求详细时再展开
  • 附上书名、章名、阅读位置，让它知道你在哪儿读

11. 风险

风险影响应对
EPUB 排版千奇百怪个别书的章节切分或段落切分不准解析失败时给出明确提示并允许"按整章纯文本读"降级；不静默出错
超长段切分阈值定得不好一屏太满或太碎，影响阅读节奏阈值做成设置项（默认 160 字）；先用几本真实书验证
预生成撞到"生成中"阅读节奏被打断缓冲 5 屏 + 串行生成；撞到时显示明确状态而不是空白
润色稿质量不稳出现删信息、加评论、变摘要提示词里把"不增不减"写成硬约束；提供单屏"重新生成"
DeepSeek 接口报错或限流润色与讨论不可用退避重试；错误在对应位置就地显示，不影响阅读原文
书很大导致解析卡顿导入时页面假死解析放在 Web Worker 或分片处理，带进度提示
